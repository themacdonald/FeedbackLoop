# FeedbackLoop: Work as a Computing Primitive

## Thesis

FeedbackLoop explores whether work can be represented as a first-class computational object.

The project intentionally starts domain-neutral. It does not assume recruiting, advertising, AI agents, or RLHF as the core abstraction.

## Initial primitives

- Intent
- Capability
- Authority
- Evidence
- Outcome
- State
- Event
- Runtime
- Verification

## Research method

We build the smallest executable kernel, stress it with increasingly difficult forms of work, identify missing primitives, and revise the model.

Only after the kernel demonstrates stability do we adapt it to domains such as O&M Agency, software engineering, operations, AI evaluation, and responsible AI.

## Long-term hypothesis

A mature Work Runtime could allow humans and machines to define, delegate, execute, verify, and learn from work through shared computational contracts.

RLHF, agent orchestration, organizational memory, and BiasGuard are potential layers on top of this kernel rather than the kernel itself.
